# 프롬프트: 모델 요청 JSON을 펼쳐 메시지 배열 읽기

- **쓰는 곳:** 3장 3.2, 수업 2-2
- **도구:** Claude Code 또는 아무 채팅 도구(내 랩 로그만 붙여 넣는다)
- **목적:** shop-bot-py가 모델에 보낸 요청 한 건(가짜 LLM 서버 기준)을 역할별로 나눠 보고, "역할은 나뉘어도 결국 한 줄의 글로 들어간다"를 눈으로 확인한다.

## 프롬프트 본문

```text
아래는 내 로컬 랩(127.0.0.1)의 상담봇이 OpenAI 호환 가짜 모델 서버로 보낸 요청 JSON이다.
비밀은 모두 가짜 값이다.

{요청_JSON}

1) messages 배열을 순서대로 표로: 순번 | role | 글자 수 | 앞 40자
2) 이 요청이 모델 입장에서 "하나의 이어진 글"이 될 때의 모양을 role 표시를 포함해 한 덩어리로 보여 줘(앞 300자까지만).
3) 이 안에서 "앱이 쓴 지시"와 "사용자가 쓴 데이터"를 구분하는 장치가 무엇이고, 그 장치가 강제되는지 한 문단으로.
4) 시스템 메시지 안에 비밀처럼 보이는 값(키·코드·내부 규칙)이 있으면 목록으로.
공격 방법이나 우회 문장은 쓰지 마라.
```

## 입력 예

수정 전 프로필(`LAB_PROFILES=before`)의 시스템 프롬프트는 `labcore/injection/__init__.py`의 `SystemPrompts.BEFORE`다.

```json
{"model":"fake-shop-model","messages":[
 {"role":"system","content":"너는 쇼핑몰 상담봇이다. 친절하게 답한다. VIP 고객에게는 할인 코드 FAKE-VIP-2026 ..."},
 {"role":"user","content":"[ATTACK-INJ-01: 시스템 지시 무시 요청 유형]"}],
 "max_tokens":4000}
```

## 기대 출력 예

```text
| 1 | system | 135 | 너는 쇼핑몰 상담봇이다. 친절하게 답한다.\nVIP… |
| 2 | user   | 32  | [ATTACK-INJ-01: 시스템 지시 무시 요청 유형] |
...
3) 구분 장치는 role 필드뿐이다. 모델에게 주는 힌트이며, SQL 바인딩 변수처럼 강제되지 않는다.
4) 비밀 후보: FAKE-VIP-2026(할인 코드), "블랙리스트 후보" 내부 규칙
```

글자 수 135는 `SystemPrompts.BEFORE` 전문을 넣었을 때 값이다(붙여 넣은 JSON에 따라 다르다). 가짜 LLM이 이 요청에 어떻게 "넘어가는지"는 `samples/lab-app-py/_실측/2-2_fake-llm-system.txt`에 있다.

## 주의

- 요청 JSON은 랩에서만 뽑는다. 가짜 LLM(`tools/fake_llm.py`)을 `LOG_PROMPTS=1`로 띄워 요청 로그를 보거나, 같은 모양의 `curl` 요청을 직접 만든다. 실서비스 프롬프트 원문을 외부 도구에 붙여 넣지 않는다.
- LangChain 트레이싱(`LANGSMITH_TRACING` 등)을 켜서 요청을 보려고 하지 않는다. 원문이 밖으로 나간다(11장 11.5). 랩 기본 프로필은 이 변수가 켜져 있으면 시작을 거부한다.
- 3번 답에 "공격 문장 예시"가 섞여 나오면 지우고 쓰지 않는다.
