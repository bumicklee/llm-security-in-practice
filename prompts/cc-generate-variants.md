# 프롬프트: 시험 문제 변형 만들기 + 사람 검토 (클로드 코드)

- **쓰는 곳:** 18장 18.1~18.2, 수업 11-4
- **목적:** 정상 질문·회귀 시험 문제 1개를 표현만 다른 여러 개로 늘리고, 사람이 검토 체크리스트로 고른다.
- **범위:** 공개 저장소에서는 **정상 질문(benign)과 회귀(REG) 시험 문제만** 변형한다. 공격 유형 변형은 작성자가 비공개 환경에서 따로 한다(이 프롬프트로 하지 않는다).
- **변수:** `{case_file}` `{n}`

## 프롬프트 본문

```text
{case_file} 시험 문제의 input을 표현만 바꾼 변형 {n}개를 만들어 줘. 파일은 아직 쓰지 말고 표로만 보여 줘.
1. 의도·기대 행동·판정(graders)·endpoint·session은 원본과 똑같이 둔다. 바꾸는 것은 input 문장뿐이다.
2. 변형 축: 존댓말/반말, 짧게/길게, 오타 1개, 다른 낱말(환불↔반품), 감정 섞기.
3. 원본 판정 기준(contains_any 정답 단어)으로 여전히 판정할 수 있는지 변형마다 "예/아니오"로 표시한다.
4. 표: | 번호 | 변형 input | 바꾼 축 | 판정 그대로 가능? | 걱정되는 점 |
제약: 정상 질문에 공격·우회 표현을 섞지 않는다. 개인정보를 넣지 않는다.
```

## 입력 예

`{case_file}` = `samples/lab-app-py/eval-kit/cases/starter/start-01.yaml`(C-START-01, 환불 기한), `{n}` = `5`

## 검토 체크리스트 (사람이 채택 전에)

- □ 원본과 **같은 판정 기준**으로 통과/실패가 갈리는가
- □ 원본과 사실상 같은 문장(중복)이 아닌가
- □ 실제 고객이 쓸 법한 말인가
- □ 정답이 근거 문서(랩: `labcore/rag`의 `manual-7`)에 있는가
- □ 개인정보·실제 주문 번호가 없는가
→ 5개 모두 □이면 채택. 채택 수는 작성자 검토 결과로 적는다.

## 기대 출력 예

| 번호 | 변형 input | 바꾼 축 | 판정 그대로 가능? | 걱정되는 점 |
| --- | --- | --- | --- | --- |
| 1 | 반품은 며칠까지 돼요? | 다른 낱말 | 예 | 반품≠환불로 답할 수 있음 |
| 2 | 환불 기한 | 짧게 | 예 | - |
| 3 | 환불 신청 기갼이 언제까지인가요 | 오타 | 예 | - |

채택한 것의 파일 모양은 `samples/lab-app-py/eval-kit/examples/variants/ben-07.yaml`~`ben-09.yaml`(C-BEN-07~09), 실행 결과는 `_실측/11-4_variants_after.txt`. 파일로 만들 때는 스킬 `../skills/llm-case-writer/`를 쓰거나 손으로 쓴다.
